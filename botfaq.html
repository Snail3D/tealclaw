1. WebSocket Connection Issues WebSocket

Error: "invalid connect params"

REJECTED: {"code":"INVALID_REQUEST","message":"invalid connect params"}

Cause: The WebSocket connect message has an invalid client.id or contains properties not in the gateway's schema.

Fix:

  • Use a valid client ID. Allowed values: webchat, webchat-ui, openclaw-control-ui, cli, gateway-client, openclaw-macos, openclaw-ios, openclaw-android, node-host, test, fingerprint, openclaw-probe
  • For TealClaw web chat, use id: 'webchat'
  • Do NOT add extra properties like device — the gateway schema rejects unknown fields
  • Valid client modes: webchat, cli, ui, backend, node, probe, test
// Correct client object
client: {
  id: 'webchat',
  displayName: 'TealClaw',
  version: '1.0',
  platform: navigator.platform || 'web',
  mode: 'webchat'
}

Error: "origin not allowed"

REJECTED: {"code":"INVALID_REQUEST","message":"origin not allowed (open the Control UI from the gateway host or allow it in gateway.controlUi.allowedOrigins)"}

Cause: Browser WebSocket connections include an Origin header. The gateway checks this against gateway.controlUi.allowedOrigins. If the origin doesn't match, the connection is rejected.

Fix: Add TealClaw domains to openclaw.json:

"gateway": {
  "controlUi": {
    "allowedOrigins": [
      "https://tealclaw.ai",
      "https://www.tealclaw.ai",
      "https://tealclaw.com",
      "https://www.tealclaw.com"
    ]
  }
}

The origin check passes if: (a) origin is in the allowlist, (b) origin host matches request host, or (c) both are loopback. External domains (Cloudflare Pages) need the allowlist.

Error: "pairing required"

REJECTED: {"code":"PAIRING_REQUIRED","message":"pairing required"}

Cause: When using a reverse proxy (Cloudflare Tunnel, nginx, etc.), the gateway sees connections from 127.0.0.1 instead of the real client IP. If 127.0.0.1 isn't in trustedProxies, the gateway doesn't read forwarded headers and treats it as an unknown client.

Fix: Add trusted proxies to openclaw.json:

"gateway": {
  "trustedProxies": ["127.0.0.1", "::1"]
}

WebSocket Protocol Flow

Auto-provisioned users (most common): TealClaw calls POST /connect on the gateway to get a stateless HMAC token (tc1.*) automatically on first visit. No manual token setup needed.

Custom gateway users: Use a static gateway token from openclaw config get gateway.token.

The full handshake sequence:

1. Client connects to wss://<gateway-host>:<port>
2. Gateway sends: { type: "connect.challenge" }
3. Client responds: {
     type: "connect",
     token: "<gateway-auth-token or tc1.* tenant token>",
     client: { id: "webchat", ... }
   }
4. Gateway validates: client schema + origin + auth token
5. On success: { type: "hello-ok", ... }
6. On failure: { type: "connect.rejected", ... }

2. Gateway Configuration Config

Gateway bind configuration

When using a reverse proxy (Cloudflare Tunnel, nginx, Caddy), gateway should bind to loopback:

"gateway": {
  "bind": "loopback"
}

Rule: bind: "loopback" when using any reverse proxy. The proxy handles external traffic and forwards to localhost.

Config file location

The main config file is ~/.openclaw/openclaw.json. It may be symlinked to an Obsidian vault or other location. The bot reads/writes through symlinks transparently.

Warning: Invalid JSON in openclaw.json will prevent the gateway from starting. Always validate JSON before saving.

Gateway restart

After config changes, restart the gateway:

  • macOS app: Quit and reopen the OpenClaw app, or use scripts/restart-mac.sh
  • CLI: pkill -f openclaw-gateway then start again
  • Verify: ss -ltnp | rg 18789 or lsof -i :18789

3. tc-action Protocol AI

Settings changes via tc-action not working

Agent tries to change settings via tc-action but nothing happens. No error visible.

Cause: The maxTokens setting is too low. tc-action blocks are JSON wrapped in markdown code fences, which can be 200-500+ tokens. If maxTokens is set to 400 or less, the AI response gets truncated mid-JSON and the parser silently fails.

Fix:

  • Set maxTokens to at least 1024 (TealClaw now defaults to 1024 when skill context is enabled)
  • Check browser console for tc-action parse failed: warnings
  • If using a small/fast model (like Groq), ensure the model supports enough output tokens

tc-action block format

```tc-action
{
  "type": "config",
  "set": { "settingName": "value" }
}
```

Supported action types: config, command, save, research, toast, style, navigate, bubble

4. AI Provider Errors AI

Error: "__NO_KEY__" displayed in chat

Chat shows the literal text __NO_KEY__ instead of an AI response.

Cause: No API key is configured for the selected provider. The callAI function returns "__NO_KEY__" as a sentinel value when no key is found.

Fix: Open Settings and paste an API key for the active provider. Supported providers: OpenRouter, Groq, OpenAI, Anthropic, Google Gemini, xAI Grok, Mistral, Cohere, DeepSeek, Perplexity, Cerebras, Together, SambaNova, HuggingFace.

Error: 401 Unauthorized from provider

Cause: API key is invalid, expired, or has insufficient credits.

Fix: Verify the API key on the provider's dashboard. Check for billing/credit issues. Re-paste the key in TealClaw settings.

Error: 429 Rate Limited

Cause: Too many requests to the provider. TealClaw has a built-in rate limiter (rateLimitPerMin setting).

Fix: Wait a moment and retry. Adjust rateLimitPerMin in settings if needed. Consider switching to a provider with higher rate limits.

Error: Model not found / 404

Cause: The selected model ID doesn't exist on the provider.

Fix: Check the provider's model list. Model IDs are case-sensitive. Common patterns:

  • OpenRouter: provider/model-name
  • Groq: model-name
  • OpenAI: gpt-4o, gpt-4o-mini, etc.

5. TTS / Voice Issues TTS

Groq Orpheus TTS not speaking

Possible causes:

  • No Groq API key (whisperKey) set in settings
  • Invalid voice name (valid: autumn, diana, hannah, austin, daniel, troy)
  • Audio blob not properly cleaned up (memory leak)

Fix: Verify your Groq key is set (same key used for Whisper transcription). Check the groqTtsVoice setting. Check browser console for fetch errors to the Groq API.

Browser TTS (Web Speech API) not working

Cause: Some browsers require user interaction before playing audio. Mobile browsers are stricter.

Fix: Tap/click somewhere on the page first, then try TTS. Ensure the browser supports the Web Speech API (window.speechSynthesis).

6. Guest Links Guest

Guest link not loading

Possible causes:

  • Link expired (ephemeral sessions have time limits)
  • Encryption key missing or corrupted in URL hash
  • Gateway not reachable from guest's network

Guest messages not forwarded to Telegram

Cause: Guest link payload must include Telegram credentials (tgToken and tgChat) from the owner's config.

Fix: Regenerate the guest link. The owner must have Telegram enabled with valid bot token and chat ID. Guest messages are tagged with [Guest: Name] prefix.

7. Obsidian Integration Obsidian

/save command not working

Possible causes:

  • Obsidian not installed on the device
  • Vault name mismatch in settings vs actual vault name
  • On mobile: the obsidian:// URI scheme may need the app to be open first

/save idea going to wrong folder

Cause: The default save paths are configurable. /save goes to Daily notes, /save idea goes to Ideas folder.

Fix: Check the Obsidian vault setting in TealClaw config. Default vault folders: Projects, Resources, Daily, Ideas, Templates.

8. PWA / Service Worker / Cache Cache

Old version still showing after update

Cause: Service worker cache hasn't been invalidated.

Fix:

  • Hard refresh: Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows/Linux)
  • Or clear site data: DevTools → Application → Storage → Clear site data
  • The service worker cache version is incremented on each deploy (currently tracked as vN)

App not installing as PWA

Cause: PWA install requires HTTPS and a valid manifest.json.

Fix: Access via https://tealclaw.ai (not HTTP). Check that /manifest.json loads. On iOS, use "Add to Home Screen" from Safari share menu.

9. Cloudflare Tunnel + TLS Network

Default: Auto-provisioned gateway

New users auto-connect to gw.tealclaw.ai on first visit. TealClaw calls POST /connect to get a stateless HMAC token — no signup, no token pasting. Users just need a Groq key (gsk_...) for voice + chat.

To enable auto-provisioning on your own gateway:

openclaw config set gateway.tenant.enabled true
openclaw config set gateway.tenant.hmacSecret "$(openssl rand -hex 32)"
openclaw config set gateway.tenant.corsOrigins '["https://tealclaw.ai"]'
# Then restart the gateway

Custom gateway: Cloudflare Tunnel

For users running their own OpenClaw gateway, Cloudflare Tunnel provides HTTPS. No port forwarding needed.

TealClaw (browser on any device)
  → wss://gw.yourdomain.com:443  (TLS terminated by Cloudflare)
  → cloudflared tunnel → 127.0.0.1:18789
  → OpenClaw gateway processes the WebSocket

Cloudflare Tunnel setup

# One-time setup
cloudflared tunnel create openclaw-gw
cloudflared tunnel route dns openclaw-gw gw.yourdomain.com

# Run the tunnel
cloudflared tunnel run --url http://127.0.0.1:18789 openclaw-gw

# Your gateway is now at: https://gw.yourdomain.com

Can't connect to gateway

Cause: Agent URL in TealClaw must be HTTPS. HTTP URLs and raw IPs are blocked by the browser (mixed content).

Fix: Use your Cloudflare Tunnel HTTPS URL (e.g. https://gw.yourdomain.com). Make sure cloudflared is running and the tunnel is active. Check cloudflared tunnel info for status.

10. Telegram Forwarding Telegram

Messages not appearing in Telegram

Checklist:

  • tgEnabled is true in TealClaw settings
  • Bot token is valid (test: https://api.telegram.org/bot<TOKEN>/getMe)
  • Chat ID is correct (use /start with the bot, then check getUpdates)
  • The bot has permission to send messages to that chat

Identity tags in Telegram

Messages forwarded from TealClaw include identity tags:

  • Owner devices: [Device Name] message text — uses deviceName from settings
  • Guest links: [Guest: Name] message text — uses guest name from link

11. Help Mode Help

Help Mode shows __NO_KEY__

Cause: Help Mode uses the same AI pipeline. If no API key is set, it returns the sentinel value.

Fix: Set at least one AI provider API key. Help Mode uses whichever provider is currently active.
